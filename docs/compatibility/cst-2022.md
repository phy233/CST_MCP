# CST 2022 兼容性问题记录

> 更新于 2026-08（测试体系重构后）。历史问题 #1–#4 已由兼容层解决，
> 保留原记录以追溯设计动机；当前架构与残余风险见下文「当前状态」。

## 1. 参数获取接口不兼容 (`project.model3d`) — ✅ 已解决

**历史现象：** CST 2022 的 COM 接口中 `project` 对象未暴露 `model3d` 属性
（CST 2023+ 引入），直接调用 `GetNumberOfParameters`/`RestoreDoubleParameter` 会崩溃。

**现行方案：** `core/compatibility/parameters.py::list_parameter_values` 按
`model3d → modeler → project` 顺序探测 COM 参数接口，全部不可用时走即时 VBA 查询
（`GetNumberOfParameters`/`RestoreParameterExpression`/`RestoreDoubleParameter` +
临时文件回读）。参数写入 (`change_parameter`/`define_parameters`) 始终走 VBA
`StoreDoubleParameter`/`StoreParameters`，与 2022 兼容。响应携带
`compatibility.transport`（`python_api` / `immediate_vba`）供调用方判断通道。

## 2. Python 版本限制 (`cst.interface` 版本检查) — ✅ 已解决

**现行方案：** `cst` 包只支持 Python ≤3.9，通过进程边界隔离：

- MCP/CLI 测试进程：仓库 `.envs/mcp`（Python 3.12，`requires-python >= 3.12`）；
- CST Worker：uv 管理的 `.envs/cst39`（Python 3.9，`CST_WORKER_PYTHON` 或
  `.cst_config.json` 配置），由 `mcp_server/proxy.py` 拉起并校验版本。

`skills/cst-runtime-cli/scripts/pyproject.toml` 声明 `requires-python = ">=3.9,<3.10"`，
runtime 全部 112 个文件通过 AST `feature_version=(3,9)` 语法检查（有测试保障）。

## 3. MCP 适配器层单元测试损坏 — ✅ 已解决

旧 `adapter.py`/`TOOL_SPECS` 架构已移除；`mcp_server/tests` 现在只验证
`server.py`/`proxy.py`/`config.py` 的现行契约（工具清单来自 Runtime，MCP 层
不直接导入 Runtime 内部模块，有 AST 测试保障）。

## 4. Python 语法兼容性冲突 (3.9 vs 3.12+) — ✅ 已解决

Runtime 源码全面使用 `from __future__ import annotations` 与 3.9 兼容语法；
MCP 层与 Runtime 层由进程边界隔离，互不要求对方的解释器。

## 当前状态（2026-08 核查结论）

### 兼容层架构（`core/compatibility/`）

- **COM 访问集中**：`lib/` 层零 COM 属性访问；`core/` 仅 `modeler`（2022 支持）
  与 `cst.results`（2022 可用）两条通道；`model3d`/`FarfieldCalculator`/
  `GetNumberOfParameters` 全部收敛在兼容层，缺失时返回结构化
  `unsupported_feature`（`phase=compatibility` + `feature`/`required_capability`），
  绝不静默降级。
- **版本画像**：`detect_compatibility_profile`（环境变量 `CST_RUNTIME_CST_VERSION`
  覆盖 → `cst.results.get_version_info` → 安装路径年份 → sys.modules），
  `profile_for` 再按实际工程对象探测 `model3d`/`modeler`/`schematic` 能力。
  未知版本（2023–2025 等）**不猜测 VBA 语法**，版本化构造器统一抛
  `unsupported_feature`（`required_capability=known_cst_version`）。
- **错误可见性**：VBA 提交走 `error_gateway.py` 的文件状态侧信道
  （arm/status 文件 + 碰撞拒绝），CST 的 VBA 编译/运行错误被分类为
  `vba_runtime_error`/`vba_compile_or_host_error`，不再出现假成功。

### 已知 2022 精确兼容错误（真机测试直接验收）

| feature | required_capability | 触发 |
|---|---|---|
| `results.2d` | `result2d` | get-2d-result（2022 无 2D 提取） |
| `results.list_all` | `results_all_items` | list-result-items filter_type=all |
| `transform.destination` | `transform.destination` | transform-shape 非空 destination |
| `mesh.fpbavoid_nonreg_unite` | `mesh.fpbavoid_nonreg_unite` | set-mesh-fpbavoid-nonreg-unite |
| `units.electrical` | `units.set_electrical_unit` | define-units 非默认电学单位 |
| `monitor.frequency_range` | `single_frequency_efield_hfield` | 2022 E/H 场监视器非单频 |

对应真机用例：`test_cst_setup.py`（Z12）、`test_cst_modeling.py`（M8）、
`test_cst_results.py`（R3）、`test_cst_integration.py`（test_41）等。

### 残余风险与待办

1. **2023–2025 版本归 unknown**：保守拒绝一切版本化 VBA（用户环境为 2022，无影响）。
2. **超表面 EM 设置 VBA 是 2022-only**：`em_setup.py` 的
   `unit_cell_boundary_vba`/`floquet_port_setup_vba`/`plane_wave_vba`/
   `frequency_domain_solver_vba` 只按 2022 手册生成，对 2026 反向抛
   `unsupported_feature`（`cst2022_em_setup`）；与上游 2026 行为有意相反。
3. **远场导出真机验收缺失**：`export-farfield-grid/cut` 需要带远场结果的第二
   基准工程（可经 `CST_TEST_PROJECT` 注入），列入后续扩展。

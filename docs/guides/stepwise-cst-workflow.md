# 分步骤 CST 工作流

本指南给人类使用者说明默认工作方式。具体工具参数以 MCP 或 Runtime Registry 为准，超表面辅助规则见 [CST 超表面设计 Skill](../../skills/cst-metasurface-design/SKILL.md)。

## 人类主导、Agent 辅助

用户负责目标、总体设计、主要物理机制、参数硬边界、成本预算、验收标准和最终取舍。Agent 负责整理工程状态、提出有依据的候选建议，并通过 MCP 或 Runtime 执行经授权的重复建模、扫参、优化和结果整理。

Agent 可以在用户已经批准的模板、参数范围、预算和停止条件内连续完成同质工作，不需要每一步重新询问；改变主要拓扑、目标、硬边界、预算、工程路径或覆盖策略时，必须暂停并交还用户决定。本流程不把 Agent 定位为端到端或全自动设计者。

## 1. 明确任务

确认工程来源、目标、可修改范围、工作频段、验收指标、自动化范围和预算，以及是否允许保存、关闭、复制或仿真。已有工程默认先制作或使用明确的工作副本。

## 2. 只读检查

仅在任务开始、初始状态未知或目标不唯一时检查精确工程路径、参数、实体、材料、端口、边界、监视器、求解器、结果树、锁文件和当前 Session。已有明确且未变化的任务上下文时，不在每次业务调用前重复这组检查。

## 3. 形成单步计划

普通设计迭代一次计划一个边界清楚的动作，例如修改一个参数、创建一个实体、设置一种边界或增加一个监视器。重复建模或优化任务可以把多个同质动作纳入一个已批准任务卡，但必须说明输入、硬边界、预期变化、预算、停止条件，以及是否包含结果导出或异步求解等必要检查。

## 4. 记录检查点

普通修改前可创建轻量 History checkpoint。高风险几何变化或恢复操作使用物理工程 checkpoint；它会保存并关闭工程、等待解锁，再复制 `.cst` 与伴随目录。

## 5. 执行并信任成功返回

公开接口没有返回错误并给出结构化成功状态时，充分相信 CST 已成功执行对应 VBA。普通参数、材料、几何、布尔、边界、端口、监视器和求解器配置调用前后，不重复读取参数、实体、配置或 History 来证明执行成功。

必要检查只用于结果导出等文件产物、异步求解完成与结果取得，以及错误、超时或 ambiguous 后的副作用判断。删除、覆盖、关闭等操作仍确认目标和授权，但这属于权限边界。科学设计是否正确继续由仿真结果和用户审查判断。

## 6. 用户审查点

完成几何和物理设置后，在首次高成本求解前向用户报告结构、材料、端口/激励、边界、监视器、假设、未验证项和预算。用户已经批准优化或扫参任务卡后，可在该边界内继续后续 trial；超出边界时再请求确认。

## 7. 仿真和结果

启动求解后使用等待/状态工具，不重复提交启动命令。确认没有新增 CST 错误日志并出现目标 Run ID，再读取结果。报告结果来源、单位、公式和工程版本。

## 8. 记录并决定下一步

MCP 自动保存工具交互。Agent 通过工作笔记记录设计假设、用户确认和阶段结论，并把事实、推断和建议分开。最终由用户决定接受候选、回退、调整目标或停止。

## 管道的定位

管道是可选快捷方式，不是默认入口。只有用户明确接受、已查看展开步骤、无需中间设计决策且停止条件清楚时才使用。重复建模和受控优化可以在批准边界内使用管道减轻人工负担；普通探索性设计仍优先采用可调整的原子步骤。

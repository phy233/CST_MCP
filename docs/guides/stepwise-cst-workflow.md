# 分步骤 CST 工作流

本指南给人类使用者说明默认工作方式。具体工具参数以 MCP 或 Runtime Registry 为准，超表面物理规则见 [CST 超表面设计 Skill](../../skills/cst-metasurface-design/SKILL.md)。

## 1. 明确任务

确认工程来源、目标、可修改范围、工作频段、验收指标以及是否允许保存、关闭、复制或仿真。已有工程默认先制作或使用明确的工作副本。

## 2. 只读检查

检查精确工程路径、参数、实体、材料、端口、边界、监视器、求解器、结果树、锁文件和当前 Session。多个工程或目标不唯一时停止写操作。

## 3. 形成单步计划

一次计划一个可验证动作，例如修改一个参数、创建一个实体、设置一种边界或增加一个监视器。说明输入、预期变化、验证方式和失败后如何判断是否已执行。

## 4. 记录检查点

普通修改前可创建轻量 History checkpoint。高风险几何变化或恢复操作使用物理工程 checkpoint；它会保存并关闭工程、等待解锁，再复制 `.cst` 与伴随目录。

## 5. 执行并验证

工具成功返回后继续检查其实际承诺：参数读回、实体存在、配置 inspect、日志、Run ID、结果节点或非空导出文件。`add_to_history()` 和状态文件 `OK` 不替代这些证据。

## 6. 用户审查点

完成几何和物理设置后，在求解前向用户报告结构、材料、端口/激励、边界、监视器、假设和未验证项。除非用户已经授权无人值守流程，否则等待确认后再运行高成本仿真。

## 7. 仿真和结果

启动求解后使用等待/状态工具，不重复提交启动命令。确认没有新增 CST 错误日志并出现目标 Run ID，再读取结果。报告结果来源、单位、公式和工程版本。

## 8. 记录并决定下一步

MCP 自动保存工具交互。Agent 通过工作笔记记录设计假设、用户确认和阶段结论。根据验证结果决定接受、回退、调整一个因素或停止。

## 管道的定位

管道是可选快捷方式，不是默认入口。只有用户明确接受、已查看展开步骤、无需中间调整且停止条件清楚时才使用；否则采用原子工具逐步执行。

# 分步骤优化循环

## 任务定义

开始前确认：

- 只读基线工程和实际工作副本；
- 目标类型、方向、阈值和计算频段；
- 可调参数、初值、上下限和相互约束；
- 最大有效 trial、最长时间和无改进停止轮数；
- 每轮必须导出的结果及其验收方式。

目标可以是指定频点 S 参数、带宽、幅相误差、极化转换率、增益或明确表达式。多目标任务不能只用一个未解释的加权值掩盖各指标。

## 基线

先检查参数和结果来源，运行或读取一个经过验证的 baseline trial。记录工程快照、Run ID、参数、目标值、结果文件和异常日志。没有可信基线时不开始正式优化。

## 探针

探针是可选的决策工具，不按参数数量机械强制。以下情况值得先探针：

- 参数较多且单次仿真昂贵；
- 参数范围来自猜测；
- 可能存在强交互或边界最优；
- 用户希望先筛选敏感参数。

探针点、范围和成本先给用户确认。探针结果只用于调整参数集和范围，不自动证明全局趋势。

## 每个 trial

```text
候选生成
→ 检查范围和物理约束
→ 记录候选与假设
→ 修改工作副本参数
→ 读回参数
→ 求解并等待
→ 检查日志和新 Run ID
→ 导出并验证结果
→ 计算目标
→ tell/记录 trial
→ 判断停止条件
```

任一步失败立即结束本 trial，不把缺失结果填成数值。操作是否已生效不明确时先做 History reconciliation，不能重复提交。

## 优化器

优先让现有 `ask-study`/`tell-study` 或相应工具维护采样状态。更换 sampler 前说明原因，并确保历史有效 trial 被保留。不要为了追求轮数在已达到目标后继续运行。

## 收尾

对最佳点至少检查一次结果来源和约束；高成本任务可在用户同意后做邻域或重复验证。最终报告区分“优化器记录的最佳值”“CST 已验证结果”和“尚未验证的物理结论”。

# CST 超表面设计辅助 Skill

本 Skill 负责电磁设计判断，不负责替代 MCP 或 Runtime CLI。涉及工程操作时组合使用 `cst-mcp`；用户明确要求 CLI、MCP 未连接或操作被限制为 CLI-only 时，使用 `cst-runtime-cli`。调用状态和终止信号遵循对应执行 Skill。

## 定位与人机分工

本 Skill 服务于人类主导的设计流程。用户负责应用目标、主要物理机制、单元拓扑、材料与制造约束、参数硬边界、验收指标和最终取舍；Agent 可以基于资料和当前工程证据提出候选建议，并通过 MCP 执行经用户授权的重复建模、扫参、优化和结果整理。

Agent 建议必须标明依据、假设、权衡和未验证项，不能写成已经成立的设计结论。用户批准任务模板、参数范围、预算和停止条件后，Agent 可以在该边界内连续完成同质重复工作；需要改变拓扑、目标、硬边界、预算或工程时，重新交给用户决定。

## 默认工作方式

采用可检查的小步循环：

1. 明确用户给出的目标、结构类型和本轮授权边界；
2. 涉及已有工程且初始信息未知时，只读检查本轮需要的工程状态；
3. 提出一个供用户判断的物理假设或候选修改；
4. 由用户确认关键设计选择、参数边界和执行成本；
5. 执行本轮已批准的步骤；仅讨论方案时不调用工程写入或求解工具；
6. 接口未返回错误时，将对应 VBA 操作记录为成功执行；仅在导出、异步求解和结果读取等必要边界检查产物；
7. 记录工具交互、必要的 History/快照和阶段结论；
8. 把事实、推断和候选建议交给用户，再共同决定下一步。

不要把建模、边界、端口、求解和结果解释封装成不可调整的一键流程。管道仅在用户明确选择且其展开步骤、输入和停止条件均可见时使用。对已批准的重复建模或优化任务，可以在既定边界内连续执行多个同质步骤；触及停止条件、异常或新的物理设计判断时暂停。

## 任务路由

- 新建或理解超表面工程：先读 [requirements-and-physics-gates.md](references/requirements-and-physics-gates.md)。
- 修改几何、参数、材料或单元拓扑：读 [geometry-and-history.md](references/geometry-and-history.md)。
- 设置激励、求解或解释结果：读 [simulation-and-result-validation.md](references/simulation-and-result-validation.md)。
- 多轮演化、对比或恢复：读 [design-iteration.md](references/design-iteration.md)。
- 扫参、灵敏度探测或优化：组合使用 `cst-runtime-optimization`，由其管理任务卡、预算和 trial；若该 Skill 未安装，只整理任务卡并说明依赖缺失，不自行复制完整优化流程。

只读取当前任务所需的 reference，不要一次加载全部资料。

## 关键边界

- 驱动散射的无限周期单元通常使用 Unit Cell 边界与 Floquet 端口；Periodic 相移或本征模问题应按具体任务另行确认。有限结构的 Plane Wave 仿真通常产生散射、场或 RCS 结果，不能据此承诺普通端口 S 参数。
- 公开 MCP / CLI 接口未返回错误并给出成功状态时，充分相信 CST 已成功执行对应 VBA；普通参数、实体和配置写入不做重复的执行前查询或执行后读回。结果导出仍检查文件，异步求解仍等待完成并取得结果，错误或超时状态不明确时才检查副作用。
- 不凭经验猜测 CST VBA。陌生对象和方法先核对目标 CST 版本的本机 Online Help，再参考已验证代码。
- 默认操作工作副本。物理检查点和重放只在显式工程路径、明确用户授权和现有安全工具支持下执行。
- MCP 自动日志只覆盖工具请求与返回；设计假设、用户确认和阶段结论通过 MCP 工具 `record-agent-note` 显式记录。直接使用 Runtime CLI 时对应子命令同名（同为连字符形式 `record-agent-note`）；两者都不声称保存隐藏推理。

## 阶段输出

每一步向用户报告：本步目标、依据、实际调用、接口状态、必要的结果或产物证据、History/interaction 关联和建议的下一步。接口成功时可报告“对应 VBA 已成功执行”，不再把普通写操作标为待读回；即使候选达到局部指标，也只报告为“本次授权范围内的候选结果”，不要自行宣布设计完成。

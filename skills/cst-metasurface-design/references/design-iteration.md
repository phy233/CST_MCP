# 设计迭代与工作记录

## 人机协同闭环

默认关系是：用户确定目标或选择候选，Agent 提议下一轮及其依据，用户批准执行边界，MCP 在边界内完成重复工作，Agent 汇总事实、推断和建议，最后由用户决定继续、调整或验收。

Agent 的价值是减少重复建模、扫参、结果整理和 trial 管理负担，而不是接管最终设计。用户已经批准目标、参数范围、约束、次数或时长预算和停止条件后，Agent 可以在该范围内连续推进；改变主要拓扑、目标、硬边界、预算、工程或覆盖策略时必须暂停并重新取得用户决定。

## 一轮设计的最小结构

1. 读取当前工程与上一轮结果；
2. 写一条 `decision` 或 `plan` note，说明问题、证据和单一修改假设；
3. 需要时创建轻量 History checkpoint；高风险结构变化前创建物理工程 checkpoint；
4. 执行一个参数或几何修改；
5. 接口未返回错误时，将对应 VBA 操作记为成功，不增加参数、实体或配置读回；
6. 在用户已批准的执行范围和预算内运行仿真；
7. 读取并验证结果；
8. 写一条 `milestone` note，记录接受、拒绝或待确认。

## 结果驱动的下一步

- 谐振偏高或偏低：优先调整有效电流路径或等效加载，但一次只改一个参数；
- 频点接近但匹配差：优先调整耦合、间隙或阻抗相关参数；
- 带宽不足：先确认是否需要增加相邻谐振，再评估效率和角度稳定性代价；
- 极化转换不足：检查模式映射、结构各向异性和相位差，不能只看单条 S 参数；
- 结果异常：先排除边界、端口、网格、旧 Run ID 和参数未生效，再改结构。

## 记录内容

每轮 note 至少包含：当前工程副本、修改假设、请求参数、接口状态、必要的结果或导出产物、接受规则和回退条件。普通成功调用不要求额外父快照或读回证据；只有恢复需要、状态 ambiguous 或用户明确要求时才关联快照。已有 interaction/history journal 是事实记录；note 只补充设计意图和人工确认。

## 扫参与优化辅助

- 用户负责目标函数、变量、硬范围、约束、预算和最终取舍；
- Agent 可以草拟任务卡、候选点和停止规则，得到批准后组合使用 `cst-runtime-optimization`；
- MCP 或 Runtime 在批准边界内执行重复 trial，并保留参数、Run ID、状态、结果和失败原因；
- Agent 汇总候选排序、权衡、异常和未解决问题，不自行把局部最佳写成全局最优或最终设计。

## 停止条件

- 达到验收指标；
- 连续多轮无改进；
- 下一步会违反参数、制造或物理约束；
- CST 操作状态 ambiguous；
- 结果来源或极化/模式映射无法确认；
- 达到用户批准的次数、时长或成本预算；
- 下一步需要新的物理机制、主要拓扑或验收权衡决定；
- 用户要求停止。

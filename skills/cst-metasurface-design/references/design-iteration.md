# 设计迭代与工作记录

## 一轮设计的最小结构

1. 读取当前工程与上一轮结果；
2. 写一条 `decision` 或 `plan` note，说明问题、证据和单一修改假设；
3. 需要时创建轻量 History checkpoint；高风险结构变化前创建物理工程 checkpoint；
4. 执行一个参数或几何修改；
5. 验证结构与物理设置；
6. 用户确认后运行仿真；
7. 读取并验证结果；
8. 写一条 `milestone` note，记录接受、拒绝或待确认。

## 结果驱动的下一步

- 谐振偏高或偏低：优先调整有效电流路径或等效加载，但一次只改一个参数；
- 频点接近但匹配差：优先调整耦合、间隙或阻抗相关参数；
- 带宽不足：先确认是否需要增加相邻谐振，再评估效率和角度稳定性代价；
- 极化转换不足：检查模式映射、结构各向异性和相位差，不能只看单条 S 参数；
- 结果异常：先排除边界、端口、网格、旧 Run ID 和参数未生效，再改结构。

## 记录内容

每轮 note 至少包含：当前工程副本、父快照、修改假设、请求参数、验证证据、结果来源、接受规则和回退条件。已有 interaction/history journal 是事实记录；note 只补充设计意图和人工确认。

## 停止条件

- 达到验收指标；
- 连续多轮无改进；
- 下一步会违反参数、制造或物理约束；
- CST 操作状态 ambiguous；
- 结果来源或极化/模式映射无法确认；
- 用户要求停止。

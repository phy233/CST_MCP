# 几何、参数化与 History

## 辅助建模模式

- 忠实复现：按用户给出的拓扑、材料、尺寸和命名建立单元，不擅自改变设计意图；
- 探索性候选：Agent 可以提出参数化草模，但必须标为候选建议，并在写入工程前由用户选择；
- 重复建模：以用户批准的参考单元或建模计划为模板，创建参数变体、重复结构或一致命名的对象。

重复建模的委托边界至少包含 `project_path`、模板或目标对象、命名规则、参数及硬范围、数量，以及保存或覆盖策略。先确认一个参考单元或完整建模计划，再允许 Agent 连续执行同质动作；执行过程中不得静默改变拓扑、材料、边界或参数范围。

## 修改原则

- 一次只改变一个主要物理机制，例如槽长、贴片间隙、谐振枝节、层间距或馈源相位。
- 调用前记录请求参数、目标对象和预期影响；接口未返回错误时，直接记录对应 VBA 已成功执行，不再读回实体或参数证明执行结果。
- 用户可调尺寸使用 CST 参数或表达式，不在 VBA 中散落不可追踪的数值。
- 参数应在 History 引用前创建；顺序通常是单位、参数、材料、几何、边界/端口、监视器和求解器。
- 只有目标或输入信息未知、无法构造正确请求时才先查询一次；已有明确目标和参数时，布尔等普通建模操作前不增加防御性重复检查。
- 不理解实体作用时，不删除或覆盖它；优先在工作副本中试验。

## 成功信任与必要检查

公开 MCP / CLI 接口没有返回错误并给出成功状态时，充分相信 CST 已成功执行对应 VBA。普通参数、材料、几何、布尔、边界、端口、监视器和求解器配置均不安排重复的执行前查询、执行后 getter、实体树检查或 History diff。

必要检查限定为：

- 结果、截图或其他导出文件存在且非空；
- 异步求解完成并能够取得本轮结果；
- 接口返回错误、超时、transport error 或 ambiguous 后，在重试前判断实际副作用；
- 删除、覆盖、关闭等操作的目标和用户授权确认。

这些检查面向产物、流程完成或权限边界，不用于推翻一个没有返回错误的 CST VBA 成功状态。批量建模同样按每次接口返回判断，不增加代表样本或逐对象读回。

## 记录方式

每次修改应记录：

- 一个简短设计假设；
- `interaction_id` 和 `operation_id`；
- 修改的参数或对象；
- 接口状态、必要的结果或产物证据，以及仍未知的物理关系。

普通成功调用不要求 before/after History snapshot。只有恢复需要、状态 ambiguous、用户明确要求检查点，或准备执行已授权的高风险恢复操作时，才创建或比较 snapshot。

设计假设、用户确认和阶段结论在 MCP 中使用 `record_agent_note`；直接 Runtime CLI 使用 `record-agent-note`。工具请求和返回由 MCP interaction journal 自动记录。不要另建无法与现有 ID 关联的平行日志。

记录中区分 `user_decision`、`agent_suggestion` 和 `executed_fact`。建模成功只能说明经授权的模型操作已经完成，不能写成超表面设计已经完成或最终方案已经通过。

## 失败与恢复

- 明确未执行：用户确认后才可重试；
- 已执行：跳过，严禁重复提交；
- 当前 History 既不等于 expected-before 也不等于 expected-after：标记为 ambiguous，停止自动操作；
- 需要换分支或回退：从物理检查点创建隔离副本，再生成并审查重放计划。

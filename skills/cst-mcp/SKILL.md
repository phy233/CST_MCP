# CST MCP Skill

通过 MCP 调用 CST Runtime。MCP 服务负责协议转换和独立 Worker 进程；不要把它当作本地 CLI 的另一种写法。

## 调用原则

- 直接调用 MCP 已提供的工具；不要运行 `uv`、`bootstrap.py`、`init-workspace`、`install-cst-libraries` 或修改 MCP 配置，除非用户明确要求部署或排障。
- 每次遇到陌生工具时，以 MCP 返回的名称、描述和输入 Schema 为准。不要在本 Skill 中假设固定工具数或参数名。
- 将每个 MCP 调用的 `status`、`message`、`error_type` 和关键输出作为下一步依据。写操作失败后立即停止，不要猜测其副作用。
- 使用明确的绝对 `project_path`，仅对用户指定的工程或其工作副本进行写入和关闭操作。
- 当存在多个打开的 CST 工程或工程锁未释放时，停止写入、保存和关闭操作，并报告需要用户确认的工程。
- 将发送给MCP的内容以及MCP返回的内容显式抄送给用户。

## 先确认，再执行

对未知工程，先调用只读的工程检查工具（通常为 `inspect-project`）。确认以下信息后，才修改模型，无法直接从工程中获取的信息需要直接询问用户并从用户处得到明确回复：

1. 工程路径和预期目标；
2. 可调参数及其当前值；
3. 几何、端口、边界和远场监视器；
4. 用户允许修改的参数、范围、目标频率和验收指标。

不要直接修改用户的唯一原始工程。需要迭代或优化时，先请求或使用明确的工作副本路径，经用户确认修改结果通过验收后方可将副本的修改合并入原始工程，且修改必须通过历史树操作以确保可恢复。

## 标准工作流

### 新建工程或链接现有工程

当本MCP被启用时，需要与CST工程进行链接。`prepare-run` 的职责是复制一个已有 `.cst` 或 `.prj` 工程并建立运行目录，不能凭空创建 CST 工程。因此在开启一个新项目时需要提醒用户手动创建供CST使用的工作区，并同时创建空白`.cst`工程，并将工作区地址发送给Agent。

### 单次改参与仿真

1. 检查工程并确认参数名。
2. 调用改参工具，要求返回成功。
3. 保存修改后的工程。
4. 启动仿真，并使用等待/状态工具确认仿真结束。
5. 关闭建模会话后再读取结果；结果读取与建模会话不可混用。
6. 导出 S11、场或远场结果，并基于导出的数据报告结论。

### 优化循环

- 先确认目标函数、阈值、可调参数和几何约束。
- 参数较多时，优先调用探针和灵敏度分析工具，再缩小优化参数集。
- 每轮记录参数、指标、仿真状态和是否达到阈值。
- 达到目标、连续无改进、参数越界或仿真失败时停止；不要为了凑轮数继续运行。

## CST 特有安全规则

- `add_to_history()` 是“同步提交、异步执行结果”的接口：返回成功仅表示 VBA 指令已送达 CST，不代表命令已执行完成或执行成功。对关键建模操作要通过后续的实体、参数、结果或文件检查验证。
- S11 原始数据通常是复数，不应直接当作 dB；需要幅度 dB 时使用 `20 * log10(abs(S11))`。
- 完成仿真后，先关闭 modeler 会话，再使用 results 会话读取最新结果。
- 远场导出后不要保存工程；应按工具返回的安全建议关闭会话，避免保存已进入异常状态的 CST 工程。
- 长时间仿真使用服务提供的等待或状态查询工具，不要用重复提交启动命令代替轮询。

## MCP 失败处理

- 工具返回超时或 Worker 连接错误时，不要立刻重复写操作。先检查工程锁、CST 进程状态和最近一次操作是否已生效，检查是否链接到CST软件。
- 服务恢复后，重新读取工程状态、参数和结果，再决定是否重试。
- 不要因 `add_to_history()` 或传输层成功而宣称模型已成功建立、仿真已完成或结果有效。

## Floquet Port 与 Unit Cell 能力限制

- 当前 Floquet Port 和 Unit Cell 自动化方法仍是待完善能力，只覆盖部分初始化或历史需求。
- 通用 `define-boundary` 不能替代完整的 Unit Cell/Floquet 配置；不得据此宣称高级周期边界已经完成。
- 用户提出高级极化、模式列表、参考面、扫描角或开放边界扩展距离需求时，应明确说明自动化能力不完整，并请用户在 CST 图形界面中手动完成。
- 不得自行拼接未经目标版本本地手册验证的 VBA，也不得用通用边界工具冒充高级配置。

## 与其他 Skill 的边界

- 需要直接执行 `uv run python -m cst_runtime ...` 时，使用 `cst-runtime-cli` Skill。
- 需要 CLI 下的完整优化策略时，使用 `cst-runtime-optimization` Skill。
- 当前 Skill 只说明通过 MCP 服务调用 Runtime 的流程与安全边界，不复制 114 个工具的参数文档。
